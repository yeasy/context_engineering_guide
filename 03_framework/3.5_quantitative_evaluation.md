## 3.5 上下文管理的量化评估方法

### 3.5.1 引言：为什么需要量化评估

在上下文工程实践中，“这个优化是否有效”常常被定性地回答（“看起来好多了”），这种回答无法支撑工程决策：

- 无法判断何时停止优化（边际收益递减点在哪里？）
- 无法对比不同方案的优劣（方案 A 和 B 哪个更好？）
- 无法持续追踪系统是否在退化（性能是否降低了？）
- 无法向管理层证明 ROI（优化是否值得投资？）

本节介绍一套量化评估框架，包括相关性指标、检索质量指标、效率指标，以及如何在实践中组合使用这些指标。

### 3.5.2 相关性评分指标

检索与筛选阶段最常用的相关性指标分为两类：面向“相关/不相关”二元标注的基础指标，以及面向多等级标注的分级指标。

| 指标 | 公式 | 关注重点 |
| --- | --- | --- |
| **MRR（平均倒数排名）** | $\text{MRR} = \dfrac{1}{\text{rank}_1}$（前 $k$ 内无相关项则为 $0$） | 第一个相关结果排得多靠前，适合问答与单答案检索 |
| **Recall@k（召回率）** | $\text{Recall@}k = \dfrac{\text{前 } k \text{ 个中的相关数}}{\text{语料库总相关数}}$ | 相关信息有没有漏掉；分母必须来自黄金标注，不能从返回结果反推 |
| **Precision@k（精确率）** | $\text{Precision@}k = \dfrac{\text{前 } k \text{ 个中的相关数}}{k}$ | 塞进上下文窗口的结果里，噪声占了多少 |
| **F1@k** | $\text{F1} = \dfrac{2 \cdot P \cdot R}{P + R}$ | 精确率与召回率的调和平均，平衡“找全”和“少噪” |
| **NDCG@k** | $\text{DCG@}k = \sum_{i=0}^{k-1} \dfrac{\text{rel}_i}{\log_2(i+2)}$，$\text{NDCG@}k = \dfrac{\text{DCG@}k}{\text{IDCG@}k}$ | 综合衡量相关性强弱与排序位置，靠前位置权重更高 |

**手算示例。** 假设搜索“Python 教程”返回 10 条结果，第 1、3、6、9 位相关（共 4 条），语料库黄金标注共有 6 条相关文档：

- **MRR**：第一条相关结果在第 1 位，因此 $\text{MRR} = 1/1 = 1.00$。若第一条出现在第 2 位，则为 $0.50$。
- **Recall@10**：前 10 条找到 4 条，占总相关数 6 条的 $4/6 \approx 0.67$。
- **Precision@10**：前 10 条中有 4 条相关，即 $4/10 = 0.40$。
- **F1@10**：$2 \times 0.40 \times (4/6) / (0.40 + 4/6) = 0.50$。

计算 NDCG@k 时，若未提供全局最优的 `ideal_dcg`，将当前候选分数降序排列可得到该候选集内的理想 DCG；用于跨检索器对比时，应传入基于完整黄金标注计算的 `ideal_dcg`。下面的实现与上述公式逐项对应：

```python
import math
from typing import List, Optional


class RelevanceScorer:
    """二元与连续相关性评分工具。"""

    @staticmethod
    def mean_reciprocal_rank(retrieved_items: List[bool], threshold_position: int = 10) -> float:
        for i, is_relevant in enumerate(retrieved_items[:threshold_position]):
            if is_relevant:
                return 1.0 / (i + 1)
        return 0.0

    @staticmethod
    def recall_at_k(retrieved_items: List[bool], relevant_item_count: int, k: int = 10) -> float:
        if relevant_item_count <= 0:
            return 0.0
        return sum(retrieved_items[:k]) / relevant_item_count

    @staticmethod
    def precision_at_k(retrieved_items: List[bool], k: int = 10) -> float:
        if k <= 0:
            return 0.0
        return sum(retrieved_items[:k]) / k

    @staticmethod
    def f1_score(retrieved_items: List[bool], relevant_item_count: int, k: int = 10) -> float:
        precision = RelevanceScorer.precision_at_k(retrieved_items, k)
        recall = RelevanceScorer.recall_at_k(retrieved_items, relevant_item_count, k)
        if precision + recall == 0:
            return 0.0
        return 2 * (precision * recall) / (precision + recall)

    @staticmethod
    def ndcg(
        relevance_scores: List[float],
        k: int = 10,
        ideal_dcg: Optional[float] = None,
    ) -> float:
        if not relevance_scores or k <= 0:
            return 0.0
        dcg = sum(score / math.log2(i + 2) for i, score in enumerate(relevance_scores[:k]))
        if ideal_dcg is None:
            sorted_scores = sorted(relevance_scores, reverse=True)
            ideal_dcg = sum(score / math.log2(i + 2) for i, score in enumerate(sorted_scores[:k]))
        return dcg / ideal_dcg if ideal_dcg > 0 else 0.0


if __name__ == "__main__":
    retrieved = [True, False, True, False, False, True, False, False, True, False]
    total_relevant_count = 6  # 来自黄金标注
    print(f"MRR: {RelevanceScorer.mean_reciprocal_rank(retrieved):.2f}")        # 1.00
    print(f"Recall@10: {RelevanceScorer.recall_at_k(retrieved, total_relevant_count, 10):.2f}")  # 0.67
    print(f"Precision@10: {RelevanceScorer.precision_at_k(retrieved, 10):.2f}")  # 0.40
    print(f"F1@10: {RelevanceScorer.f1_score(retrieved, total_relevant_count, 10):.2f}")  # 0.50
```

#### 分级相关性指标

实际场景中的相关性常常分为多个等级，而非简单的“相关/不相关”，常见四级标注为：`0`（完全不相关）、`1`（部分相关）、`2`（相关）、`3`（高度相关）。标准分级 DCG 使用指数增益 $2^{\text{grade}} - 1$（对应权重 0、1、3、7），放大“高度相关文档排在最前面”的收益：

$$\text{DCG@}k = \sum_{i=0}^{k-1} \frac{2^{\text{grade}_i} - 1}{\log_2(i+2)}$$

```python
import math
from typing import List


class GradedRelevanceScorer:
    """处理 0-3 四级相关性标注的评估工具。"""

    RELEVANCE_GRADES = {0: "完全不相关", 1: "部分相关", 2: "相关", 3: "高度相关"}

    @staticmethod
    def dcg_with_grades(relevance_grades: List[int], k: int = 10) -> float:
        return sum(
            ((2 ** grade) - 1) / math.log2(i + 2)
            for i, grade in enumerate(relevance_grades[:k])
        )

    @staticmethod
    def ndcg_with_grades(relevance_grades: List[int], k: int = 10) -> float:
        dcg = GradedRelevanceScorer.dcg_with_grades(relevance_grades, k)
        ideal_grades = sorted(relevance_grades, reverse=True)[:k]
        ideal_dcg = GradedRelevanceScorer.dcg_with_grades(ideal_grades, k)
        return dcg / ideal_dcg if ideal_dcg > 0 else 0.0

    @staticmethod
    def metric_at_each_level(relevance_grades: List[int], k: int = 10) -> dict:
        counts = {grade: 0 for grade in range(4)}
        for grade in relevance_grades[:k]:
            counts[grade] += 1
        return {
            "not_relevant": counts[0],
            "partially_relevant": counts[1],
            "relevant": counts[2],
            "highly_relevant": counts[3],
        }
```

### 3.5.3 检索质量度量

单条查询容易受偶然波动影响，工程评估通常会在多组截断值（如 `k = 1, 5, 10`）上批量评估一组代表性查询，并同时报告均值、标准差与最值，避免高分样本掩盖长尾查询的退化。注意每条查询的 `total_relevant_count` 都应来自黄金标注或完整候选集，不能用当前返回列表中的相关条数代替。

```python
import statistics
from typing import List, Optional


class RetrievalQualityEvaluator:
    """单查询与批量检索质量评估（复用上文 RelevanceScorer）。"""

    def __init__(self, scorer: RelevanceScorer | None = None):
        self.scorer = scorer or RelevanceScorer()

    def evaluate_retrieval(
        self,
        query: str,
        retrieved_results: List[dict],
        total_relevant_count: int,
        top_k_values: Optional[List[int]] = None,
    ) -> dict:
        top_k_values = top_k_values or [1, 5, 10]
        is_relevant = [bool(r.get("is_relevant", False)) for r in retrieved_results]
        evaluation = {
            "query": query,
            "total_retrieved": len(retrieved_results),
            "total_relevant": total_relevant_count,
        }
        for k in top_k_values:
            evaluation[f"metrics@{k}"] = {
                "mrr": self.scorer.mean_reciprocal_rank(is_relevant, k),
                "recall": self.scorer.recall_at_k(is_relevant, total_relevant_count, k),
                "precision": self.scorer.precision_at_k(is_relevant, k),
                "f1": self.scorer.f1_score(is_relevant, total_relevant_count, k),
            }
        return evaluation

    def evaluate_retrieval_batch(
        self,
        queries: List[str],
        retrieved_results_batch: List[List[dict]],
        total_relevant_counts: List[int],
        top_k_values: Optional[List[int]] = None,
    ) -> dict:
        top_k_values = top_k_values or [5, 10]
        individual = [
            self.evaluate_retrieval(q, res, rel_cnt, top_k_values)
            for q, res, rel_cnt in zip(queries, retrieved_results_batch, total_relevant_counts)
        ]
        aggregated: dict = {}
        for k in top_k_values:
            bucket: dict = {}
            for name in ("mrr", "recall", "precision", "f1"):
                vals = [item[f"metrics@{k}"][name] for item in individual]
                bucket[name] = {
                    "mean": statistics.fmean(vals),
                    "std": statistics.pstdev(vals),
                    "min": min(vals),
                    "max": max(vals),
                }
            aggregated[f"@{k}"] = bucket
        return {
            "individual_results": individual,
            "aggregated_metrics": aggregated,
            "total_queries": len(queries),
            "average_retrieval_count": statistics.fmean(r["total_retrieved"] for r in individual),
        }
```

### 3.5.4 上下文效率指标

检索召回率高不代表上下文高效：若拼装后的文本充斥重复段落和无关背景，既浪费 Token 预算，也会稀释注意力。上下文效率可从四个维度度量：

| 维度 | 定义与计算口径 | 关键注意 |
| --- | --- | --- |
| **信息密度** | 相关片段规模 / 上下文总规模（上限截断为 1.0） | 必须基于人工或评估模型标注的 `relevant_spans` 与总上下文分别计算；若直接把现成的相关性分数乘回总长度再相除，分子分母会约掉，得到的只是原分数本身 |
| **冗余度** | $1 - \dfrac{\text{唯一 } n\text{-gram 数}}{\text{总 } n\text{-gram 数}}$（示例取 5-gram） | 英文可按空白分词，中文场景应先分词或改用字符级 n-gram |
| **覆盖率** | 上下文命中的查询关键词数 / 查询总关键词数 | 仅反映词汇层面覆盖，不能替代语义充分性评估 |
| **综合效率分数** | 按工程权重将信息密度（0.35）、非冗余度（0.25）、覆盖率（0.25）与预算内 Token 利用率（0.15）汇总到 0–100 | 四项中仅信息密度依赖外部标注；权重属于可调工程约定，而非通用常数 |

```python
from typing import List


class ContextEfficiencyAnalyzer:
    """上下文使用效率分析（粗略估算用 len // 4，生产应接入真实 tokenizer）。"""

    @staticmethod
    def information_density(context: str, relevant_spans: List[str]) -> float:
        total_tokens = len(context) // 4
        if total_tokens <= 0:
            return 0.0
        useful_tokens = sum(len(span) // 4 for span in relevant_spans)
        return min(1.0, useful_tokens / total_tokens)

    @staticmethod
    def redundancy_ratio(context: str, n: int = 5) -> float:
        words = context.split()
        if len(words) < n:
            return 0.0
        ngrams = [" ".join(words[i : i + n]) for i in range(len(words) - n + 1)]
        return 1.0 - (len(set(ngrams)) / len(ngrams))

    @staticmethod
    def context_coverage_ratio(context: str, query: str) -> float:
        keywords = set(query.lower().split())
        if not keywords:
            return 0.0
        context_lower = context.lower()
        return sum(1 for kw in keywords if kw in context_lower) / len(keywords)

    @staticmethod
    def efficiency_score(
        context: str,
        query: str,
        relevant_spans: List[str],
        max_tokens: int = 2000,
    ) -> float:
        density = ContextEfficiencyAnalyzer.information_density(context, relevant_spans)
        redundancy = ContextEfficiencyAnalyzer.redundancy_ratio(context)
        coverage = ContextEfficiencyAnalyzer.context_coverage_ratio(context, query)
        token_utilization = min(1.0, (len(context) // 4) / max_tokens)
        score = (
            density * 0.35
            + (1.0 - redundancy) * 0.25
            + coverage * 0.25
            + token_utilization * 0.15
        )
        return score * 100.0


if __name__ == "__main__":
    context = (
        "Python 是一种高级编程语言，以简洁易读著称。"
        "Python 支持过程式、面向对象和函数式编程。"
        "Python 广泛用于数据科学、机器学习和 Web 开发。"
    )
    relevant_spans = ["Python 是一种高级编程语言，以简洁易读著称。"]
    score = ContextEfficiencyAnalyzer.efficiency_score(context, "Python 编程", relevant_spans)
    print(f"上下文效率分数: {score:.1f}/100")
```

### 3.5.5 A/B 测试框架在上下文优化中的应用

比较两种上下文策略（对照组 Control vs 实验组 Treatment）时，应让**同一批查询**分别通过两套策略，再用统计检验确认改进不是随机噪声：

1. **配对 t 检验（Paired t-test）**：比较逐查询差值 $\Delta_i = y_i - x_i$，消除不同查询本身难易度带来的方差；当 $p < \alpha$（常见 $\alpha = 0.05$）时认为差异具有统计显著性。
2. **效果量（Paired Cohen's $d_z$）**：$d_z = \bar{\Delta} / s_\Delta$（使用样本标准差 `ddof=1`），衡量改进的实际幅度，避免大样本下“统计显著但业务无感”的误判。
3. **样本量估算**：配对设计在双侧显著性水平 $\alpha$ 与检验效能 $1-\beta$（如 `power=0.8`）下，所需查询数可近似为：
   $$n = \left\lceil \left(\frac{z_{1-\alpha/2} + z_{\text{power}}}{d_z}\right)^2 \right\rceil$$
   例如 $\alpha = 0.05$、`power = 0.8`、预期中等效果量 $d_z = 0.5$ 时，约需 $n = 32$ 条配对查询。

下例演示配对检验与策略对照流程；其中的 `_similarity` 仅用词重叠作演示，生产环境应替换为经过校准的语义指标、LLM-as-a-judge 评分细则或人工黄金标注，避免把字面复述误判为答案正确。

```python
import math
from typing import Callable, List
import numpy as np
from scipy import stats


class ABTestFramework:
    """面向配对查询评测的统计检验工具。"""

    @staticmethod
    def paired_ttest(
        control_group: List[float],
        treatment_group: List[float],
        alpha: float = 0.05,
    ) -> dict:
        t_stat, p_value = stats.ttest_rel(control_group, treatment_group)
        control_mean = float(np.mean(control_group))
        treatment_mean = float(np.mean(treatment_group))
        improvement = (
            (treatment_mean - control_mean) / control_mean * 100.0
            if control_mean != 0
            else 0.0
        )
        return {
            "t_statistic": float(t_stat),
            "p_value": float(p_value),
            "is_significant": bool(p_value < alpha),
            "control_mean": control_mean,
            "treatment_mean": treatment_mean,
            "improvement": improvement,
        }

    @staticmethod
    def cohen_d(control_group: List[float], treatment_group: List[float]) -> float:
        deltas = np.array(treatment_group, dtype=float) - np.array(control_group, dtype=float)
        std_delta = float(np.std(deltas, ddof=1)) if len(deltas) > 1 else 0.0
        return float(np.mean(deltas) / std_delta) if std_delta > 0 else 0.0

    @staticmethod
    def calculate_sample_size(
        effect_size: float = 0.5,
        alpha: float = 0.05,
        power: float = 0.8,
    ) -> int:
        z_alpha = stats.norm.ppf(1 - alpha / 2)
        z_beta = stats.norm.ppf(power)
        return int(math.ceil(((z_alpha + z_beta) / effect_size) ** 2))


class ContextOptimizationABTest:
    """对同一组查询执行 Control / Treatment 配对评测。"""

    def __init__(self, control_strategy: str, treatment_strategy: str):
        self.control_strategy = control_strategy
        self.treatment_strategy = treatment_strategy

    def run_test(
        self,
        queries: List[str],
        ground_truth_answers: List[str],
        llm_generate_func: Callable[[str, str], str],
    ) -> dict:
        control_scores = [
            self._similarity(llm_generate_func(self._prepare_context(q, self.control_strategy), q), gt)
            for q, gt in zip(queries, ground_truth_answers)
        ]
        treatment_scores = [
            self._similarity(llm_generate_func(self._prepare_context(q, self.treatment_strategy), q), gt)
            for q, gt in zip(queries, ground_truth_answers)
        ]
        result = ABTestFramework.paired_ttest(control_scores, treatment_scores)
        result["effect_size"] = ABTestFramework.cohen_d(control_scores, treatment_scores)
        return result

    def _prepare_context(self, query: str, strategy: str) -> str:
        return f"Using {strategy}: {query}"

    @staticmethod
    def _similarity(text1: str, text2: str) -> float:
        words1, words2 = set(text1.lower().split()), set(text2.lower().split())
        return len(words1 & words2) / len(words1 | words2) if (words1 and words2) else 0.0
```

这套量化评估框架让团队能够依据数据而非主观判断衡量上下文工程的效果。建议在每个优化周期中定期进行这些评估。
